# VissLink v1.0.0

Configuration de référence : `examples/iot-viessmann-v1.0.0.yaml`. C'est le
seul exemple du dépôt ; il charge les composants publiés
(`github://ubikyo/visslink@v1.0.0`).

Installation cible :

- Vitocrossal 300 CU03 (brûleur VGM I-2) ;
- Vitotronic 300 KW3 (`209C`) ;
- A1 radiateurs, M2 plancher chauffant avec Vitotrol 200 ;
- ECS Vitocell 300-V ;
- Wemos D1 Mini (ESP8266), Home Assistant.

## 1. Écritures : plus aucune option d'autorisation

Les commandes implémentées sont directement utilisables. Les options suivantes
n'existent plus. Une configuration qui les déclare est refusée à la
validation.

| Option supprimée | Où |
|---|---|
| `enable_writes`, `enable_mode_writes`, `enable_m2_mode_write` | `visslink:` |
| `enable_schedule_writes`, `enable_dhw_setpoint_write`, `enable_heating_setpoint_writes` | `visslink:` |
| `validated_days` | `visslink_boost:` |
| `allow_write` | `number` (consignes Party), `switch` (Éco/Party) |
| `status` | `number`, `switch` |

**Migration :**

- supprimer ces lignes du YAML ;
- une configuration v0.x qui les avait à `false` devient inscriptible.

Les protections techniques restent :

- **Adresses :** seules celles des listes blanches (`write_guard.h`). Aucune
  écriture arbitraire n'est possible, ni sur `0x0846` ni sur une pompe.
- **Valeurs :**
  - consignes en degrés entiers, dans les limites internes du registre ;
  - programmes `00`/`03`/`05` ;
  - Éco/Party `00`/`01` ;
  - blocs horaires valides.
- **Une écriture à la fois :** 10 s au moins entre deux, demande abandonnée
  après 120 s sans émission, jamais de nouvel essai automatique.
- **Relecture de la valeur actuelle avant d'écrire :** une modification faite
  au panneau ou à la Vitotrol n'est jamais écrasée.
- **Relecture de confirmation :**
  - après chaque écriture, la valeur relue doit être exactement celle écrite ;
  - après une commande de programme, l'autre circuit est relu aussi ;
  - après une commande Éco/Party, l'autre fonction du même circuit est relue
    aussi.
- **Bouclage ECS :** sauvegarde en flash avant écriture, puis restauration
  vérifiée, avec récupération après une coupure.
- **Au démarrage :** aucune commande n'est envoyée.

| Fonction | Registres | Limites internes |
|---|---|---|
| Consignes confort/réduite A1 | `0x2306` / `0x2307` | 16–23 / 10–20 °C, confort ≥ réduite |
| Consignes confort/réduite M2 | `0x3306` / `0x3307` | 16–22 / 14–20 °C, confort ≥ réduite |
| Consigne ECS | `0x6300` | 50–60 °C |
| Consignes Party A1 / M2 | `0x2308` / `0x3308` | 16–23 / 16–22 °C |
| Éco / Party A1 | `0x2302` / `0x2303` | `00`/`01` |
| Éco / Party M2 | `0x3302` / `0x3303` | `00`/`01` |
| Modes A1 / M2 | `0x2301` / `0x3301` | `00`/`03`/`05` |
| Programmations A1, M2, ECS, bouclage | `0x2000`, `0x3000`, `0x2100`, `0x2200` | blocs de 8 octets valides |

Les consignes confort/réduite ne sont jamais modifiées pour simuler Éco ou
Party.

## 2. Entités Home Assistant

Aucune entité VissLink n'est dans la section « Diagnostic » de l'appareil.

- **Capteurs :** toutes les mesures et tous les états.
- **Configuration :** seul le bouton « Bouclage ECS — Oublier la sauvegarde ».
- **Wi-Fi, IP et uptime :** déclarés avec `entity_category: ""` pour rester
  dans « Capteurs ».

Le résultat de chaque commande est écrit dans le journal ESPHome, au niveau
INFO :

- relecture préalable ;
- écriture ;
- « Confirmée », « Échec : relu … au lieu de … » ou « Indéterminé » ;
- « Modifiée hors de Home Assistant ».

Les entités « État modification » et « État commande » ont été supprimées. Une
anomalie réelle reste remontée par :

- « Bouclage ECS — Restauration nécessaire » (problème) ;
- « Modes A1 et M2 différents » ;
- l'état du bouclage, celui de l'éditeur et celui du climate.

Nouvelles lectures (aucune commande) :

- **Pente des courbes de chauffe :** `0x2305` / `0x3305`, 1 octet ÷ 10.
- **Parallèle des courbes de chauffe :** `0x2304` / `0x3304`, 1 octet signé,
  en K.
- **Source :** adresses et codage `getNeigungM1/M2` et `getNiveauM1/M2` de
  vcontrold pour la Vitotronic KW.

Renommages :

| Avant | Après |
|---|---|
| `Bouclage ECS — Pompe (état réel, 0x0846)` | `Bouclage ECS - Pompe bouclage` |
| `Plancher - Consigne Party` | `Plancher chauffant - Consigne Party` |

Les consignes Party sont des sliders.

Supprimé :

- les capteurs expérimentaux abandonnés, mis en commentaire dans les
  anciens exemples : consignes de départ `0x2544`/`0x3544`, `0x0845`,
  `0x0883`, `0x2906` ;
- la puissance brute `0xA38F` ;
- les exemples intermédiaires v0.x.

## 3. Vérifié et non vérifié

**Vérifié :**

- tests C++ sur PC, dont des simulations de la ligne Optolink ;
- validation de la configuration ESPHome ;
- compilation pour le D1 Mini.

**Non vérifié sur la chaudière :**

| Point | Ce que montrera l'essai |
|---|---|
| Écriture Éco/Party A1 et M2 (`0x2302`, `0x2303`, `0x3302`, `0x3303`) | documentée pour la 200 KW2 seulement, et nulle part pour `0x3302` ; la relecture dit si la KW3 l'applique |
| Écriture des consignes Party (`0x2308`, `0x3308`) | idem |
| Éco + Party simultanés | comportement de la régulation non documenté : relu et journalisé |
| M2 avec la Vitotrol 200 | si M2 est en « Fernbedienung », une écriture Optolink peut être accusée sans effet : journal « Échec », sans nouvel essai |
| Écriture du mode M2 (`0x3301`) | non documentée |
| Écriture des programmations A1, M2 et ECS par l'éditeur | jamais essayée sur cette chaudière |
| Pente / parallèle des courbes de chauffe | à comparer avec le panneau |
| Ambiance Vitotrol `0x0898`, circulateur M2 `0x3906` | cohérents, codage supposé |
| Limites internes des consignes | provisoires, choisies pour l'installation |

Ordre conseillé pour les premiers essais (détail : `docs/eco-party-v0.9.1.md`
§ 3, sans l'option `allow_write`) :

1. consigne Party A1 ;
2. Party A1 ;
3. Éco A1 ;
4. consigne Party M2 ;
5. Party M2 ;
6. Éco M2.
